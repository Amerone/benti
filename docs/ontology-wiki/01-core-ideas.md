# 01 Core Ideas

## 快速看懂

### 本体是什么

本体是对某个业务领域中：

- 有哪些对象
- 它们怎么关联
- 有哪些属性
- 哪些规则成立
- 可以推导出什么结论

进行显式、结构化表达的一种方法。

### 本体不是什么

- 不是一堆业务文档
- 不是简单词典或术语表
- 不是所有数据的总仓库
- 不是替代 LLM 的“万能推理机”

## 为什么 Agent 需要本体

企业 Agent 常见失败，不是因为“没有工具”，而是因为“缺语义”。

典型症状：

- 同一个状态词在不同系统里含义不同
- 能查到数据，但不知道数据之间的业务关系
- 能执行流程，但无法解释为什么这样做
- 多 Agent 协作时没有共享语义基线

本体的作用，就是把这些原本隐含在系统、文档和经验里的业务语义显式化。

## 展开理解

### 本体的 6 块积木

1. 类 / 概念（Class）  
   比如 `Order`、`Customer`、`Shipment`

2. 实例 / 个体（Individual）  
   比如 `Order_A1024`、`customer_vip`

3. 关系（Object Property）  
   比如 `hasCustomer`、`hasAllocation`

4. 属性（Data Property）  
   比如 `qcPassed`、`requiredQty`

5. 约束 / 公理（Axiom）  
   比如“只有质检通过的库存占用才满足可发货条件”

6. 推理（Reasoning）  
   基于规则和事实，推出新的结论

### TBox 和 ABox

这是理解本体最关键的一组概念。

- TBox：术语层 / 结构层 / 规则层  
  定义“世界应该长什么样”

- ABox：事实层 / 数据层  
  记录“世界里现在实际有什么”

一个简单对照：

| 层 | 作用 | 类比 |
|---|---|---|
| TBox | 概念、关系、约束 | 数据库 Schema / OOP class |
| ABox | 实例、事实、状态 | 表数据 / new 出来的对象 |

### 本体和知识图谱的区别

容易混淆，但不能混用。

- 本体：更偏“语义框架和规则定义”
- 知识图谱：更偏“事实数据和实例连接”

一句话记：

> 本体定义结构，知识图谱填充事实。

## 深入一点

### 对企业 Agent 来说，本体真正值钱的不是“知道更多”

而是下面四件事：

1. 统一概念  
   避免不同系统里同名异义、异名同义

2. 统一规则  
   把业务判断从零散代码和 Prompt 中抽出来

3. 统一解释  
   让结论能回溯到事实与约束

4. 统一协作  
   让人、系统、Agent 使用同一语义底座

### 一句话模型

如果只记一个句子，可以记这个：

> 本体是企业 AI 的语义层；它把“业务对象 + 业务关系 + 业务规则 + 业务事实”组织成一个可查询、可推理、可解释的结构。
