一、业务场景



1.1 背景

某精密零件制造商（汽车配件 / 消费电子均适用）在新产品导入（NPI）阶段，需对试制批次进行系统性工艺验证。核心业务问题是：在工艺参数尚未稳定、规格仍可能调整的情况下，如何可靠地记录试验数据并做出可审计的放行判定。

1.2 具体场景

产品：注塑成型精密外壳（新型号首次试产）

试验目标：验证新模具在三种温度梯度下的尺寸稳定性，确认量产工艺窗口

参与角色：

操作员：在生产线录入或采集测量数据

工艺工程师：建立试验方案，设定规格，分析结果

质量主管：审核异常，作出放行决策



试验结构：

Trial T001（注塑工艺验证）

Batch B01（低温梯度 183°C，50件）

Batch B02（中温梯度 188°C，50件）

Batch B03（高温梯度 193°C，50件）

测量参数：注塑温度（主参数）

质量规格：Spec_v1，温度范围 180–195°C

三、代码开发方向



3.1 文件结构

3.2 模块一：本体文件（Protégé 建模，不写代码）

在 Protégé 中完成类层次、属性定义、约束、SWRL 规则，导出 .ttl 文件。不涉及手工编码。

核心类：Trial / Batch / Parameter / Measurement / Specification / Result

关键设计：Specification 支持版本化（命题一基础），推理结果持久化推理链字段（命题三基础）

SWRL 规则（3条）：Rule_Pass / Rule_Fail_High / Rule_Fail_Low

3.3 模块二：graph.py — 图数据库封装（约120行）

封装 Fuseki 的读写操作，是所有模块的底层依赖。

核心方法：

query(sparql) — 执行 SELECT 查询，返回结构化结果

update(sparql_update) — 执行 INSERT/DELETE 操作

insert_measurement() — 写入一条测量数据三元组

update_measurement_result() — 将推理结论写回图谱（含完整推理链字段）

get_available_parameters() — 动态查询已注册参数列表（命题二核心）

register_parameter() — 运行时注册新参数（命题二实现）

3.4 模块三：inference.py — 推理引擎（约100行，MVP核心）

包含两个核心函数，直接支撑命题一和命题三。

evaluate_single(value, upper, lower, spec_version) — 核心判定逻辑，返回结论 + 规则名 + 偏差证据

run_inference(meas_id, ...) — 单条推理并持久化到图谱

rerun_after_spec_change(old_spec, new_spec, ...) — 命题一核心：规格变更后重推理所有历史数据，返回差异报告

设计决策：MVP 阶段判定逻辑直接写在 Python 中（而非纯 SWRL 引擎），原因是可解释性和可调试性优先。生产阶段再迁回推理引擎。

3.5 模块四：qa.py — 自然语言问答（约80行，命题三）

三步流程：自然语言 → SPARQL 生成 → 执行查询 → LLM 生成中文答复

Few-shot 样本库（15条）覆盖：

推理链查询（"M007为什么是Fail？"）

规格变更影响查询

批次通过率统计

参数历史数据查询

关键：system prompt 明确包含推理链字段（inferenceRule / specVersion / deviation），使 LLM 能解释判定依据而不只是复述结果。

3.6 模块五：app.py — Streamlit 前端（约150行）

四个 Tab，每个直接对应一个验证命题：

六、知识积累的体现



6.1 知识积累的本质差异

传统系统的数据积累是量的增加：更多行、更多列、更多文件。本体系统的知识积累是结构的增厚：每次运行都在向图谱中沉淀可被推理的新节点。



维度

传统系统

本体系统

积累方式

数据 + 数据 = 更多数据

数据 + 推理 + 决策 + 反馈 = 可计算的知识

知识载体

数据库行，静态存储

图谱节点，带语境、可关联、可推理

知识消亡

专家离职，知识随之消失

线性增长（更多数据）

6.2 五个层次的知识积累

层次一：事实知识（每次录入即积累）

每条 Measurement 写入图谱时，不只是存了一个数字，而是存了一个有完整上下文的事实节点——包含参数类型、所属批次、试验、时间戳、操作员、传感器来源。这条事实可以在任何未来时刻被查询、关联、推理，是永久的、有语境的知识节点，而不是一个会被覆盖的数据库行。

积累效果：100次试验后，图谱里形成完整的、跨时间、跨批次、跨产品的工艺记录网络。



层次二：推理知识（每次判定即积累）

推理结果不只是写回一个 Pass/Fail 字段，而是把整个推理过程持久化：使用了哪条规则、依据哪个规格版本、上下限是多少、偏差值是多少、推理时间是何时。六个月后，任何人（包括AI）都能重建当时的判定逻辑，而不需要依赖人的记忆或纸质档案。

积累效果：推理知识本身成为可查询的资产，支撑合规审计、工艺复盘、责任追溯。



层次三：决策知识（每次人工介入即积累）

当主管对异常数据做出 Override 决策时，这个决策本身成为图谱节点，记录：覆盖了哪条数据、原结论是什么、最终结论是什么、由谁决定、决策时间、判断依据、参考证据。

积累效果：下一次遇到类似情形，系统可以主动提示历史决策案例供参考，专家经验从「只存在于大脑中」变成「可检索、可复用、可传承的组织知识」。



层次四：模式知识（跨Trial分析后自动提炼）

当多个 Trial 完成归档后，系统跨 Trial 运行分析推理，发现规律后写入图谱作为工艺洞察节点，包含：发现内容、证据Trial列表、样本量、置信度、改进建议、生成时间。

积累效果：洞察节点会影响下一个Trial的规格设定建议，形成知识飞轮——数据→洞察→规格优化→更好的数据。



层次五：规格演化知识（版本链即进化史）

每次规格升版，不是覆盖，而是在图谱中延伸一条版本链。每个新版本节点记录：新参数值、生效时间、取代哪个旧版本、变更原因、变更人、证据节点（指向哪条洞察）。

积累效果：任何时刻都能查询「这个规格是怎么一步步演变到今天的，每次变更的数据依据是什么」——这是任何传统系统无法提供的工艺演化史。
