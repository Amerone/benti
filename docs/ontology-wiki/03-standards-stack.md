# 03 Standards Stack

## 快速记忆

把常见标准和工具压成一张表：

| 层 | 代表 | 作用 |
|---|---|---|
| 数据表示 | RDF | 用三元组表达事实 |
| 语义建模 | OWL / RDFS | 定义类、关系、约束、逻辑 |
| 约束校验 | SHACL | 校验数据是否符合形状与规则 |
| 查询操作 | SPARQL | 查询和操作 RDF 图 |
| 建模工具 | Protégé / WebProtégé | 设计和维护本体 |
| 推理执行 | HermiT / Pellet | 做一致性校验和推理 |
| 运行存储 | GraphDB / Jena / Fuseki 等 | 存储、查询、推理 |
| 程序接入 | Owlready2 等库 | 在代码里读写本体 |

## 展开理解

### RDF

RDF 是事实表达的基础形式。

它的核心结构是三元组：

- 主语
- 谓语
- 宾语

比如：

- `Order_A1024 hasCustomer Customer_Zhangsan`
- `Order_A1024 hasAllocation Alloc_01`

RDF 很适合表达“事实是什么”。

### OWL

OWL 是在 RDF 之上的语义增强层。

它更适合表达：

- 类层级
- 关系约束
- 等价类
- 推理前提

RDF 更像“表达句子”，OWL 更像“定义逻辑”。

### SHACL

SHACL 更偏数据校验。

当你希望检查：

- 某类对象是否必须有某个属性
- 某个字段是否必须满足类型或数量约束
- 某些结构是否满足数据质量要求

SHACL 非常适合做“形状校验”。

### SPARQL

SPARQL 是 RDF 世界的查询语言。

可以把它粗略理解成：

> 面向图语义数据的 SQL

它负责把本体和事实“用起来”。

## 工具怎么选

### 入门和建模

- Protégé Desktop：适合单机实验、最小建模、推理验证
- WebProtégé：适合多人协作维护

### 推理和验证

- HermiT：常见 OWL 推理机
- Pellet：常见推理机

### 运行时存储

如果你重点要：

- RDF / OWL 标准兼容
- SPARQL 查询
- 语义推理

优先考虑 RDF 三元组库。

如果你重点要：

- 图遍历
- 路径分析
- 属性图生态

可以考虑 Neo4j 这类属性图库。

但两者不要混为一谈。

## 深入一点

### 一个务实的技术选型原则

如果你的目标是：

- 统一业务语义
- 显式表达规则
- 让 Agent 做可解释判断

那么更像是在做“语义层工程”。

这时典型组合通常是：

- Protégé / WebProtégé
- RDF / OWL
- 推理机
- SPARQL
- 三元组库

### 一个够用的最小工具链

对大多数试点项目，下面这套就够了：

1. 用 Protégé 建模
2. 用少量 ABox 数据验证
3. 用 HermiT 检查推理结果
4. 用 Owlready2 写最小程序联调
5. 需要多人协作或线上运行时，再迁移到三元组库

## 和 Palantir Ontology 的关系

### 不要把它们当成同一层东西

经典语义网栈主要回答的是：

- 如何表达事实
- 如何表达语义约束
- 如何校验
- 如何推理
- 如何查询

Palantir Ontology 主要回答的是：

- 如何把业务对象暴露给运营与应用
- 如何把业务动作建成受控写操作
- 如何把逻辑、权限、对象展示和应用接入放在一起

所以两者不是简单替代关系。

### 可以这样理解两条路线

| 路线 | 关注重点 |
|---|---|
| RDF / OWL / SHACL / SPARQL | 语义表达、标准兼容、可推理约束 |
| Palantir Ontology | 运营对象模型、动作模型、应用接入、治理控制 |

### 一个更务实的判断

如果你当前问题更像：

- 需要开放标准本体交换
- 需要显式逻辑推理
- 需要 RDF 图查询

那么经典语义网栈更直接。

如果你当前问题更像：

- 需要把业务对象直接给应用和 Agent 用
- 需要对对象做受控写回
- 需要把权限、安全、界面和动作一起治理

那么 Palantir Ontology 这种产品化路线更贴近落地。

### 两者真正的交叉点

Palantir 官方在类型参考里明确提到，其数据类型设计受 RDF、OWL、XSD 等概念启发。

所以可以把它理解成：

- 在思想上借鉴本体工程和语义建模
- 在工程上偏向企业 operational system

这也是为什么读本页标准栈之后，再读 Palantir 专题页会更顺。
